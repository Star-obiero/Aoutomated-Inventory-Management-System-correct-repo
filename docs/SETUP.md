# Setup Guide (for the administrator)

Estimated time: 30 to 45 minutes.

## 1. What you need

- An n8n instance (cloud or self-hosted). Check your plan's execution limit: every row of a file import triggers a separate run of the engine.
- A Google account with a spreadsheet for the inventory
- A Telegram account
- A Gmail account connected to n8n for emails

## 2. Prepare the Google spreadsheet

Create one spreadsheet with two tabs. Header rows are in [`templates/`](../templates).

**Inventory** tab, row 1:

```
Product ID | Item name | Quantity | Unit | Reorder level | Low stock alerted | Updated at
```

**Inventory Change Log** tab, row 1:

```
Timestamp | Request ID | Product ID | Item name | Action | Previous quantity | Change quantity | New quantity | Status | Message | Request source
```

Product IDs are generated by the system in the form `P001`, `P002`. If you already have products, give them IDs in the same form.

## 3. Create the Telegram bot

1. In Telegram, message **@BotFather** and send `/newbot`.
2. Follow the prompts and copy the token. Treat it like a password and never commit it.

## 4. Import the workflows

1. In n8n, import `workflows/inventory-stock-update-engine.json`.
2. Import `workflows/bulk-inventory-import-telegram.json`.
3. The exported files have their identifiers replaced with placeholders. Re-select them in the nodes:
   - **Google Sheets credential** on every Google Sheets node, and choose your spreadsheet and the two tabs.
   - **Gmail credential** on the email nodes.
   - **Telegram credential** (one credential created from your bot token) on all Telegram nodes: Telegram Trigger, Reply, Acknowledge, Download File, Send Summary to Chat, Send Answer. Use the **same** credential on all of them. Different credentials cause "chat not found" errors.
4. In the engine, set the low-stock alert recipient in the **Email Low-Stock Alert** node.
5. In the bulk workflow, open **Call Engine** and select the imported engine workflow. Refresh its inputs so `suppress_alert` appears.

The engine file already includes the `suppress_alert` input and the extra condition on **Needs Low-Stock Alert?** that allow muting per-row alerts during file imports.

## 5. Configure access

Open the **Route Message** node. Edit the settings at the top:

```js
const ALLOWED_CHAT_IDS = ['REPLACE_WITH_MANAGER_CHAT_ID'];
const MANAGER_EMAIL = 'manager@example.com';
const MUTE_ALERT_EMAILS_DURING_FILE_IMPORT = true;
```

To find a chat ID, have the person send `/myid` to the bot (it works for everyone, even before they are authorised). Add the number to `ALLOWED_CHAT_IDS`.

Only people in this list can change or query stock.

## 6. Test checklist

Run in test mode first (click **Execute** on the canvas, then message the bot), then publish.

1. `/myid` returns a chat ID.
2. `list` and `low stock` give sensible answers.
3. Send `samples/01_clean_import.csv` as a File with the caption `dry run`. The sheets must not change.
4. Send it again without the caption. New rows appear in Inventory and success entries in the Change Log.
5. Send it a third time. Every row must come back as a duplicate.
6. Send `samples/02_import_with_errors.csv` (dry run, then real). Bad rows must be rejected with reasons and logged.
7. Send `samples/03_excel_import.xlsx` to prove the Excel path.
8. Try `dry run add 10 rice`, `add 10 rice`, `remove 500 rice`.
9. Confirm the summary email arrives and no per-row low-stock emails arrive for files.
10. Delete the test products from the Inventory sheet before real use. Change Log entries can stay.

## 7. Publish

Click **Publish** on both workflows. Until the bulk workflow is published, the bot only answers once after you click Execute. The engine has no public trigger, so publishing it is safe.

## 8. Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| The bot never replies | Workflow not published, or Execute not clicked in test mode |
| "Chat not found" | A node uses a different bot credential from the trigger. Use one credential everywhere |
| "Not authorised" | Chat ID missing from `ALLOWED_CHAT_IDS`, or workflow not republished after editing |
| File ignored | Sent as a photo or an unsupported type. Send as a File |
| Error at Call Engine | Engine not published, wrong workflow selected, or inputs not refreshed |
| Per-row low-stock emails still sent for files | Mute setting is `false`, or the engine edits are missing |
| Rows rejected as duplicates | Their Request IDs already succeeded. Use new IDs for new changes |
| Two workflows fight over the bot | Telegram allows one webhook per bot. Use a separate bot per workflow |

## 9. Security notes

- Never commit tokens, credentials or real inventory exports. The workflow files here have identifiers replaced with placeholders.
- Keep `ALLOWED_CHAT_IDS` as short as possible.
- Review the Change Log regularly.
